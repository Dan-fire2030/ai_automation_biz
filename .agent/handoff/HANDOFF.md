## 試したこと・結果
- **最大の発見＝クリック座標のスケール問題**。`getBoundingClientRect()` はCSS px（`innerWidth`＝2560）だが `computer` のクリック座標はスクリーンショット座標（幅1558）で、**≒0.609倍の変換が必須**。これを知らずにrectの値をそのままクリックしていたため、投稿①の最初の2回は「クリックがモーダル外に着弾→typeが虚空に消える」状態だった。**SKILL.mdが「初回type破棄の既知バグ」としていた症状の少なくとも一部はこれが真因**（ただし補正後も1回空になったのでバグ自体も別に存在しそう）
- **画像添付は成功**。`find` で hidden file input を探すと**モーダル側とタイムライン側の2つがヒットする**ので、モーダル側のrefに `file_upload`。添付前検証は `[data-testid="attachments"]` 配下imgの `blob:` src。**投稿後の検証で `[data-testid="tweetPhoto"]` はヒットしない**ので `a[href*="/photo/"]` か img src の `/media/` で判定する（最初これで「画像が付いてない」と誤判定しかけた）
- **スレッドは3つの失敗モードで中断**。①`addButton` 直後のtypeがReact確定前で文字化けして混入（実例：`る伝か正由1. 理を面らえ`）→wait必須 ②`/compose/post` へnavigateしてもモーダルが開かずインライン投稿欄だけになることがあり、モーダル前提のセレクタが全空振り ③`addButton` クリックで `/compose/post` へ遷移が走り、入力済みの1ポスト目が丸ごと消滅。**アカウントへの副作用はゼロ**（プロフィール最新は②・下書き一覧も空）を確認して停止した
- SKILL.mdの落とし穴表を3件→**7件**に拡充。「未確立・次回の宿題」セクションを新設し、スレッド在庫の場所も明記した
