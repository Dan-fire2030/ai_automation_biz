# X投稿スキル（バズ型＋承認済み原稿の自動投稿）

## 役割分担と境界（必須）

- **原稿作成**：メインエージェントが本スキルの「型」に沿って `x/YYYY-MM-DD/` に作成（日付フォルダは作成日基準・MEMORY.md）
- **承認**：ユーザーが文面OKを出す。**承認のない原稿は絶対に投稿しない**
- **投稿実行**：x-posterサブエージェント（`.claude/agents/x-poster.md`）に委譲。投稿ボタンまで自動・投稿後検証まで実施
- noteは「公開ボタンはユーザー」、Xは「承認済み原稿を投稿ボタンまで自動」が確定した境界（2026-07-19ユーザー決定）

## 原稿の型（書籍ノウハウ・2026-07-19取り込み）

### 共通：キャッチーな1行目（最重要）
読まれるかどうかは**最初の一文で決まる**。タイムラインで足を止めさせる書き出しの型：
- 断言型：「断言しますが」「何度も言いますが」「結論から言うと」
- 希少型：「9割の人が知らない」
- 引用型：「〇〇さんが言っていた」（有名人の言葉の引用は強力）

⚠️ハルトの口語（フランク・語りかけ・「…！」「〜」）とミックスすること。型をそのまま使うと堅くなりAI文体になる（MEMORY.mdの文体ルール優先）。例：「断言しますが、これ知らないと損です」→「これ、知らないとほんとに損だと思うんです」のように温度感を調整。

### 型1：単発ポスト（毎日の小ネタ3本ルーティン）
- 140字以内・盛らない・体験ベース（従来ルールどおり）
- 1行目に上記のフックを入れる
- **箇条書きを使うときは見栄え重視**：各行の文字数（行の長さ）を揃える

### 型2：スレッド投稿（深掘り・note誘導向き）
1つのポストに自分でリプライを繋げて内容を深掘りする形式。読者の滞在時間が伸びる→XのAI評価が上がる→伸びやすい。

- 1ポスト目の型：
  ```
  〇〇で重要なことは5つ。
  1.〇〇
  2.〇〇
  3.〇〇
  4.〇〇
  5.〇〇
  それでは、ひとつずつ詳しく解説していきます。
  ```
- 2ポスト目以降：「1.〇〇についてですが、……」と1項目ずつリプライで解説
- **各ポストの文字数をある程度揃える**（1ポスト目140字なのに2ポスト目1,000字はNG・読みづらい）

### 型3：画像の活用
- 箇条書きポストの内容を画像化／伝えたいメッセージをメモ帳風スクショに／図解を添付→タイムラインでの視認性が格段に上がる
- 「この投稿は有益そうだ」「情報が網羅されてそうだ」の印象→**ブックマークされやすい**
- 画像生成はAGENTS.mdルールどおり**Codexに委譲**し、`x/images/YYYY-MM-DD/`（投稿文と同じ日付）に保存

## 原稿ファイル形式

- 単発：従来どおり本文のみのMD（`x/YYYY-MM-DD/NN_小ネタ_◯◯.md`）
- スレッド：1ファイル内を `---` で区切り、1ブロック＝1ポスト
- 画像付き：本文の末尾に `画像: x/images/YYYY-MM-DD/xxx.png` 行を書く（**この行は投稿本文に含めない**）
- 投稿済みマーカー：投稿完了後、ファイル先頭に `<!-- posted: YYYY-MM-DD HH:MM -->` を追記（二重投稿防止）

## 投稿手順（Chrome自動操作）

**2026-07-19初実戦済み（単発3本・画像なし・アカウント=@tonaria_ai）**。画像添付とスレッドは未実戦のため初回に要検証。

1. `tabs_context_mcp` →新規タブで `https://x.com/home`。ログイン済みか確認（未ログインならユーザーに依頼して中断）
2. `https://x.com/compose/post` へnavigate（投稿モーダルが開く・実戦確認済み）
3. 本文入力：`div[data-testid="tweetTextarea_0"]`（実在確認済み）を実クリック→computer typeで入力。日本語複数行もtypeでそのまま入る（ClipboardEvent paste方式は不要だった）
4. **⚠️type後に必ずDOM検証**：モーダル表示直後の初回typeは丸ごと破棄されることがある（3本中2本で再現・待機を増やしても再発）。エディタが空なら同じ内容をもう一度type（リトライ1回で全件解決した実績）
5. **本文照合はDraft.jsブロック単位で**：`el.querySelectorAll('[data-block="true"]')` で行配列に分解して原稿と比較する。innerText照合は空行が`\n\n\n`に見えて使えない
6. 画像添付（未実戦）：`input[data-testid="fileInput"]` に `file_upload`→プレビュー確認
7. スレッド（未実戦）：1ポスト目入力後に「＋」ボタン（`data-testid="addButton"`）→次ポストを入力→繰り返し→「すべてポスト」
8. 投稿：「ポストする」ボタンをクリック（スクショ座標クリックで動作）。成功トーストは画面下部「ポストを送信しました。表示」——ただしトーストで完了と判断しない
9. **投稿後検証（必須）**：自分のプロフィールへnavigate。**最初のarticleは固定ポスト**（`div[data-testid="socialContext"]`の有無で判別）なので最新投稿は2番目以降を見る。投稿URLは article内の `a[href*="/status/"]>time` の親アンカーhref、投稿時刻は同time要素の `datetime` 属性（UTC）から取得
10. 原稿ファイルに投稿済みマーカーを追記

## 落とし穴まとめ（2026-07-19初実戦分を反映）

| 症状 | 原因 | 対策 |
|---|---|---|
| typeしたのにエディタが空 | モーダル表示直後の初回type破棄（待機延長でも再発） | type後にDOM検証→空なら再type（1回で入る） |
| 本文照合が常に不一致 | innerTextは空行ブロックが改行を余計に産む | `[data-block="true"]`で行配列比較 |
| 検証で別のポストを見てしまう | プロフィール最上部は固定ポスト | `socialContext`の有無で固定を除外し2番目以降を見る |
