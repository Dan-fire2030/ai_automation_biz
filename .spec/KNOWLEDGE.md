# KNOWLEDGE - ドメイン知識・調査結果

## 業務・ドメイン知識
- 事業テーマ：超小型企業・施設向けのAI業務自動化支援。会社員のまま副業で開始し、最終的にストック収益化(ほぼ不労)を目指す
- 入口ニッチ：行政書士(知人にいる)。定型書類業務が多くAI自動化と相性◎。2026年改正行政書士法でICT活用が職責として明文化され業界に追い風
- 行政書士の76%は年商500万円未満(令和5年実態調査)。**本人に高額リテイナーは売れない**。本人は「月3万パイロット+月2〜3万保守+紹介パートナー」と位置づける
- 高額リテイナー(月8〜15万)の本命は行政書士の顧問先中小企業(従業員5〜30人の建設業者など)。建設業は人手不足ワースト1位(帝国データバンク2026年4月調査で69.6%が正社員不足)
- 行政書士法の制約：無資格者が官公署提出書類の作成を業として行うのは違法。売るのは「代行」ではなく「行政書士本人が使う効率化の仕組み」

## 調査・リサーチ結果

## 技術的な知見
- 技術構成の型：入口(Gmail/LINE公式/Googleフォーム) → n8nクラウド or GAS → Claude API(転記・下書き・要約) → 出口(スプレッドシート/Wordひな形/メール下書き)
- デモ01の実装(2026-07-04)：GASからClaude APIはUrlFetchApp直叩き(GAS用SDKなし)。モデルは claude-haiku-4-5(2026-07-04にユーザー指定で変更。質が足りなければ claude-sonnet-5 等へ1行変更で戻せる)、構造化出力(output_config.format の json_schema)でJSON保証、APIキーはスクリプトプロパティ管理。コストは1相談あたり1円以下(Haiku)。コードは `.output/demo01_相談受付デモ/`
- デモ02の実装(2026-07-07)：「更新期限の自動監視＆催促文の下書き」。デモ01と同じGAS5ファイル構成・同じClaude呼び出し型を踏襲。**きっかけが違う**——01はフォーム送信(受動)、02は時限トリガーで毎朝シート走査(能動・取りこぼし防止)。核は**ステージ制**(90日前→60→30→直前→超過)で、前回より緊急なステージに進んだときだけ下書きを作り毎日スパムしない設計。列は見出し名で引き(列順変更に強い)、必要書類は「目安」明記で法的助言を回避。ロジックはローカルのnodeでステージ判定・スパム防止・エスカレーションを検証済み。コードは `.output/demo02_期限管理デモ/`。01(転記の入口)＋02(催促・期限管理)で行政書士3定型作業のうち2つをデモでカバー
- Claude APIは入力データを学習に使用しない — 士業への提案でデータ取り扱いの説明材料になる
- 開発はダミーデータで行い、本番データは納品後に接続。認証情報はパスワード管理ツールで管理

- **【重要】事業の主従を反転(2026-07-07)**：AI活用の**継続伴走コーチングを主軸**、自動化ツール提供は**プラスオプション**に。理由＝実績ゼロの今、ツール納品は売りにくいが「使い方を教える」は参入障壁が低く早く提供でき、信頼を作ってからツールへ繋げられる(教育→信頼→ツール深掘りの導線)。①提供形態=継続伴走コーチング(月額。単発研修でなく継続)②ストック化=コーチングのノウハウを教材化(動画講座/プロンプト集/テンプレ集)して不労収益へ③初回の行政書士へはコーチングとツール両方見せて選ばせる。**ねじれ注意**：コーチングは労働集約なので、教材化でストック化しないと「頑張るほど不労から遠ざかる」。この反転に伴い06(提供メニュー)/09(提案書)/10(台本)はツール前提の記述をコーチング主軸へ改訂が必要
- **コーチングの差別化＝「繋がったAI」(2026-07-07)**：単なる「ChatGPTにコピペ」ではなく、AIを先生の実ツール(Gmail/Drive/Sheets/カレンダー)や外部サービスにMCPで繋ぎ、"実データに対して動くAI"を使えるようにするのが売り。普通の人=非エンジニアには設定(MCP構築/OAuth/APIキー)ができないので差別化＆継続価値(DIYで真似されない)になる。**現実的な切り分け**：繋ぎ込みの構築は私が担当、先生は"繋がったAIを使う"ことに集中。コーチングは2段構成(1段目=基礎プロンプトはつかみ／2段目=本命の連携活用)。**士業ゆえデータ設計が最重要**——先生のGoogleアカウント内で完結する繋ぎ方を優先し外部MCPにPIIを流さない。コーチング/ツールの境目は「都度指示して使う=コーチング／指示すら不要で自動=ツール」。設計は `.output/phase0/12_AIコーチング設計と提案.md`。11(自動化カタログ)は"オプションの在庫"として位置づけ直す
- **提案の"武器の在庫表"(2026-07-07)**：分野別AI自動化提案カタログ `.output/phase0/11_AI自動化提案カタログ.md`。08=聞くこと／11=作って提案すること、で役割分担。全分野共通の鉄板3種(A受付自動化=デモ01/B催促案内=デモ02応用/C期限監視=デモ02)を土台に、6分野それぞれ2〜3の具体案を「対象作業→今の流れ→自動化後→構成→作れる度★→効果→地雷」で記述。最初のパイロットは実証済みの鉄板3種から選ぶのが安全。AIの得意(下書き・分類・翻訳・期限監視)/不得意(代行・法的判断・100%保証・採択保証)の線引きも明記
