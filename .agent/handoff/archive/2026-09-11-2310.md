## 試したこと・結果

### 成功したアプローチ

- **⭐⭐実画面のスクショをメインセッションで取得できるようになった（8本目にして初）。** 7本目までは4経路とも不可でユーザー手動撮影だった。確立した経路＝
  1. **macOSの画面収録権限をClaudeに付与してもらう**（2026-09-11ユーザー実施。これが無いと `screencapture` は `could not create image from display` で落ちる）
  2. `osascript` で Chrome の該当タブをアクティブ化（`set active tab index of front window`）
  3. `open -a "Google Chrome"` で前面化 → `screencapture -x`
  4. `sips --cropOffset` で切り出し
  - **⚠️`sips --cropOffset` の引数は (Y, X) の順。`-c` も (height, width)。** XY順で渡して1回外した
  - **⚠️画面共有バナーが上端に写る**ので offsetY を 232 まで下げて除外した
  - **⚠️Claude in Chrome の `save_to_disk` はパスを返さない**（画像は見えるが保存できない）。`computer-use` のブラウザ権限も「閲覧のみ」で同一ターン再申請しても通らない。**この2経路は今後も使えない**
- **実態ヒアリングが15本連続で効いた。** 今回聞き出したのは①レシートをAIに読ませたことが一度もない ②そもそも自分の手元に紙が溜まらない（全部メール・画面）。これで「毎週AIの記事を書いている本人が、レシートだけ一度もやっていない」という告白型に組めた
- **実演で想定が外れたので、外れたほうを書いた（3回連続）。** 仕込んだ金額系の引っかけ2つは素の版で両方防がれた。代わりに見つかったのは「紙に書いていないことを静かに埋める」挙動で、**記事の核（税額合計が1,281→554に変わる）はここから出た**。想定どおりに事故っていたら、もっと弱い記事になっていた

### 失敗したアプローチ・つまずき

- **⛔⛔公開時刻23:05＝また夜帯（8本連続）。この回の唯一の露出施策が「朝〜昼公開」だったのに、それが実行されなかった。** 新シリーズは朝〜昼の数字をいまだに1本も持っていない。**当日夜に下書きが完成すると、その場で公開する流れになる**——8回連続で同じ結末なので、次回は「前日までに下書きを完成させ、翌朝に押す」を作業手順として先に固定すること
- **⛔Codexが使えなかった。** `gpt-6-astra` に対し「もっと新しいCodexが必要」というサーバー側エラー。**CLIを 0.144.5 → 0.154.0（npm最新）へ更新しても同じ**＝`~/.codex/config.toml` のモデルがCLIから使えない状態。さらに**ユーザー側でCodexが利用制限中**と判明。→ 今回限りの例外としてPillowで自作した（4・5本目の前例）。**次回もCodexを使うなら、config.tomlのモデル行を先に直す必要がある**
- **⚠️自作の図解で1枚、タグと本文が重なっていた。** 原寸目視で発見して修正。Codexに限らず**自分で描いた画像も必ず原寸で見る**
