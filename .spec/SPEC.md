## 2. 機能要件

### 機能A：転記（画像→申請書ドラフト）
- 入力：Driveの指定フォルダに置かれた**在留カード＋パスポートの画像**（今回は入管庁等の公開見本画像を使用）
- 処理：GASがClaude API（vision）で券面をOCR→構造化（氏名ローマ字/漢字・生年月日・国籍・性別・在留資格・在留期限・在留カード番号・旅券番号等）
- 出力：**在留期間更新許可申請書（公式Excel様式をSheets化したもの）** の該当セルに転記した「申請書ドラフト」
- 転記範囲：申請人等作成用1の、身分証から取得できる項目に限定（それ以外は空欄のまま＝先生が書く欄）

### 機能B：突合チェック（申請書×原本→チェック表）
- 入力：記入済みの申請書シート（デモでは**わざと誤りを仕込んだサンプル**）＋原本画像
- 処理：Claude APIが原本と申請書を項目ごとに照合
- 出力：「チェック結果」シート——項目／申請書の記載／原本の記載／判定（OK・不一致・要確認）／指摘コメント
- デモで見せる誤り例：氏名ローマ字のスペル違い・生年月日の西暦/和暦ズレ・在留カード番号の1文字違い

## 3. 技術構成（デモ01/02の型を踏襲。2026-07-16にExcel版を追加＝当日実演の本命）

- **Excel版（本命）**：Python＋openpyxlで入管庁の公式xlsxを直接読み書き＋Claude API直叩き（`excel版/`。先生がExcel/Word中心の見込みのため、「いつものExcelファイルがそのまま出てくる」を実演する）
- **GAS版（Googleユーザー向け在庫＋当日バックアップ）**：Google Apps Script（スプレッドシートbound）＋ UrlFetchApp → Claude API直叩き
- モデル：`claude-haiku-4-5`（vision対応）で開始。OCR/照合の精度が不足したら `claude-sonnet-5` に1行変更で切替
- 構造化出力（json_schema）でOCR結果のJSONを保証
- APIキーはスクリプトプロパティ管理／コストは1実行数円以下想定
- 起動：デモではメニューボタン（onOpenメニュー）から手動実行（時限トリガー化は本番導入時）

## 4. セキュリティ・法務要件（提案書§3と一致させる）

- デモは**100%公開見本・架空データ**。本物そっくりの在留カード画像を自作しない（偽造懸念の回避＝入管庁公開の「見本/SAMPLE」入り画像を使う）
- 本番設計の前提：データは先生の環境（PC・アカウント）内で完結／私の環境に保存しない／マイナンバーは扱わない／Claude APIは入力を学習に使わない
- **本番の基盤は先生の環境に合わせる（2026-07-16方針決定）**：先生はExcel/Word中心の見込み→本番は**Excelファイルを直接読み書きするローカル版を第一候補**とし、GAS版は「体験を見せるデモ」の位置づけ。コアロジック（プロンプト・スキーマ・セルマッピング・照合）は基盤非依存に分離済みで移植は小さい。当日ヒアリング（台本①-4）で環境を確定させる
- 申請書の**作成代行ではない**：出力はドラフト＋チェック表で、最終確認・提出は先生（行政書士法の線引き）
