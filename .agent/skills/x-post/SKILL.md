# X投稿スキル（バズ型＋承認済み原稿の自動投稿）

## 役割分担と境界（必須）

- **原稿作成**：メインエージェントが本スキルの「型」に沿って `x/YYYY-MM-DD/` に作成（日付フォルダは作成日基準・MEMORY.md）
- **承認**：ユーザーが文面OKを出す。**承認のない原稿は絶対に投稿しない**
- **投稿実行**：x-posterサブエージェント（`.claude/agents/x-poster.md`）に委譲。投稿ボタンまで自動・投稿後検証まで実施
- noteは「公開ボタンはユーザー」、Xは「承認済み原稿を投稿ボタンまで自動」が確定した境界（2026-07-19ユーザー決定）

## 原稿の型（書籍ノウハウ・2026-07-19取り込み）

### 共通：キャッチーな1行目（最重要）
読まれるかどうかは**最初の一文で決まる**。タイムラインで足を止めさせる書き出しの型：
- 断言型：「断言しますが」「何度も言いますが」「結論から言うと」
- 希少型：「9割の人が知らない」
- 引用型：「〇〇さんが言っていた」（有名人の言葉の引用は強力）

⚠️ハルトの口語（フランク・語りかけ・「…！」「〜」）とミックスすること。型をそのまま使うと堅くなりAI文体になる（MEMORY.mdの文体ルール優先）。例：「断言しますが、これ知らないと損です」→「これ、知らないとほんとに損だと思うんです」のように温度感を調整。

### 型1：単発ポスト（毎日の小ネタ3本ルーティン）
- 140字以内・盛らない・体験ベース（従来ルールどおり）
- 1行目に上記のフックを入れる
- **箇条書きを使うときは見栄え重視**：各行の文字数（行の長さ）を揃える

### 型2：スレッド投稿（深掘り・note誘導向き）
1つのポストに自分でリプライを繋げて内容を深掘りする形式。読者の滞在時間が伸びる→XのAI評価が上がる→伸びやすい。

- 1ポスト目の型：
  ```
  〇〇で重要なことは5つ。
  1.〇〇
  2.〇〇
  3.〇〇
  4.〇〇
  5.〇〇
  それでは、ひとつずつ詳しく解説していきます。
  ```
- 2ポスト目以降：「1.〇〇についてですが、……」と1項目ずつリプライで解説
- **各ポストの文字数をある程度揃える**（1ポスト目140字なのに2ポスト目1,000字はNG・読みづらい）

### 型3：画像の活用
- 箇条書きポストの内容を画像化／伝えたいメッセージをメモ帳風スクショに／図解を添付→タイムラインでの視認性が格段に上がる
- 「この投稿は有益そうだ」「情報が網羅されてそうだ」の印象→**ブックマークされやすい**
- 画像生成はAGENTS.mdルールどおり**Codexに委譲**し、`x/images/YYYY-MM-DD/`（投稿文と同じ日付）に保存

## 原稿ファイル形式

- 単発：従来どおり本文のみのMD（`x/YYYY-MM-DD/NN_小ネタ_◯◯.md`）
- スレッド：1ファイル内を `---` で区切り、1ブロック＝1ポスト
- 画像付き：本文の末尾に `画像: x/images/YYYY-MM-DD/xxx.png` 行を書く（**この行は投稿本文に含めない**）
- 投稿済みマーカー：投稿完了後、ファイル先頭に `<!-- posted: YYYY-MM-DD HH:MM -->` を追記（二重投稿防止）

## 投稿手順（Chrome自動操作）

**実戦済み：単発（2026-07-19・3本）／画像添付（2026-07-20・1本）**。**スレッドは2026-07-20に失敗・手順未確立**（後述）。

### ⚠️ 最重要：クリック座標のスケール変換（2026-07-20判明）

`getBoundingClientRect()` が返すのは**CSS px**（`window.innerWidth`＝2560）だが、`computer` ツールのクリック座標は**スクリーンショット座標**（幅1558）。**両者は別物なので、rectの値をそのままクリックしてはいけない。**

```js
// JS側で必ず変換してから座標を返す
const s = 1558 / window.innerWidth;  // ≒0.609（スクショ幅は実測値を使う）
const r = el.getBoundingClientRect();
return { x: Math.round((r.left + r.width / 2) * s),
         y: Math.round((r.top + r.height / 2) * s) };
```

変換を忘れるとクリックがモーダル外に着弾し、続くtypeが虚空に消える。**「初回typeが破棄される既知バグ」として記録されていた症状の少なくとも一部はこれが真因**（ただし補正後も1回空になったので、バグ自体も別に存在する）。モーダルの表示位置は毎回変わるため、座標のハードコードは禁止。毎回rectから再計算する。

1. `tabs_context_mcp` →新規タブで `https://x.com/home`。ログイン済みか確認（未ログインならユーザーに依頼して中断）
2. `https://x.com/compose/post` へnavigate（通常は投稿モーダルが開く）
   - **⚠️ URLが `/compose/post` のままモーダルが開かず、ホームのインライン投稿欄だけが描画されることがある**（2026-07-20遭遇）。この状態では `[role="dialog"]` が存在せず、モーダル前提のセレクタが全部空振りする。サイドバーの `a[data-testid="SideNav_NewTweet_Button"]` での回避も、このときボタンが未描画（ラベルなしの灰色ピル）で効かなかった
3. 本文入力：`div[data-testid="tweetTextarea_0"]` を実クリック→computer typeで入力。日本語複数行もtypeでそのまま入る（ClipboardEvent paste方式は不要）
   - **⚠️ 二重エディタ問題**：`document.querySelector('[data-testid="tweetTextarea_0"]')` は状況により**タイムライン側の投稿欄**を掴む。モーダルが開いているなら `closest('[role="dialog"]')` で絞る。ただし上記のとおりモーダルが開かないケースもあるので `[role="dialog"]` を必須条件にはせず、全件列挙して中身を確認するのが安全
4. **⚠️type後に必ずDOM検証**：モーダル表示直後の初回typeは丸ごと破棄されることがある（3本中2本で再現・待機を増やしても再発）。エディタが空なら同じ内容をもう一度type（リトライ1回で全件解決した実績）
5. **本文照合はDraft.jsブロック単位で**：`el.querySelectorAll('[data-block="true"]')` で行配列に分解して原稿と比較する。innerText照合は空行が`\n\n\n`に見えて使えない
6. **画像添付（2026-07-20実戦済み・この手順で通る）**
   1. `find` で「hidden file input for media upload」を検索する。**モーダル側とタイムライン側の2つがヒットする**ので、モーダル側のrefを選ぶこと
   2. そのrefに `file_upload`（1MB強で数秒）
   3. 添付前検証：`[data-testid="attachments"]` の存在＋配下imgの src が `blob:` で始まるか
   4. 原稿末尾の `画像: ...` 行は投稿本文に含めない
7. **スレッド（2026-07-20に失敗・手順未確立。実行前にユーザーへ相談すること）**
   想定手順は「1ポスト目入力→「＋」（`data-testid="addButton"`）→次ポスト入力→繰り返し→「すべてポスト」」だが、**この素朴な流れでは動かなかった**。判明している失敗モード：
   - **`addButton` 直後のtypeが文字化けして混入**：「＋」で `tweetTextarea_1` が生成され `activeElement` も自動で移るが、**Reactの確定前にtypeすると文字順がぐちゃぐちゃに混ざる**（実例：`る伝か正由1. 理を面らえ`、末尾は同じ文字が延々リピート）。→ クリック後に必ず2〜3秒の `wait` を挟む
   - **`addButton` のクリックで入力済み本文が消滅**：インライン投稿欄で1ポスト目入力に成功（照合match:true）後、`addButton` をクリックしたらURLが `/compose/post` に遷移し `tweetTextarea_0` が空に。1ポスト目が丸ごと失われた
   - 最低限の防御：**クリックのたびに本文が消えていないか再照合する**。壊れたスレッドを公開アカウントに残すくらいなら中断して報告する
8. 投稿：「ポストする」ボタンをクリック（スクショ座標クリックで動作）。成功トーストは画面下部「ポストを送信しました。表示」——ただしトーストで完了と判断しない
9. **投稿後検証（必須）**：自分のプロフィールへnavigate。**最初のarticleは固定ポスト**（`div[data-testid="socialContext"]`の有無で判別）なので最新投稿は2番目以降を見る。投稿URLは article内の `a[href*="/status/"]>time` の親アンカーhref、投稿時刻は同time要素の `datetime` 属性（UTC）から取得
   - **画像付きの検証は `[data-testid="tweetPhoto"]` を使わない**（投稿後ページではヒットしない・2026-07-20に「画像が付いていない」と誤判定しかけた）。`a[href*="/photo/"]` の存在か、imgのsrcに `/media/` を含むかで判定する
10. 原稿ファイルに投稿済みマーカーを追記
11. **中断するときは副作用の有無まで確認して報告する**：プロフィール最新ポスト＋下書き一覧（`https://x.com/compose/post` のドラフト）を見て、部分投稿や壊れたスレッドが残っていないことを確かめる

## 落とし穴まとめ（2026-07-19・2026-07-20の実戦分を反映）

| 症状 | 原因 | 対策 |
|---|---|---|
| クリックが効かない／typeが虚空に消える | **rectのCSS px座標をそのままクリックしている**（スクショ座標とは別スケール） | JS側で `1558/innerWidth`（≒0.609）を掛けてから返す |
| typeしたのにエディタが空 | 上記スケール問題が主因の可能性大。補正後も初回type破棄は稀に起きる | 座標変換を先に疑う→それでも空なら再type |
| typeした文字が混ざって化ける（`る伝か正由1. 理を面らえ` 等） | 新規フィールド生成直後にtypeし、Reactの確定が間に合っていない | クリック後に2〜3秒 `wait` を挟んでからtype |
| 本文照合が常に不一致 | innerTextは空行ブロックが改行を余計に産む | `[data-block="true"]`で行配列比較 |
| セレクタが全部空振り／別の投稿欄に入力される | `/compose/post` でもモーダルが開かずインライン投稿欄になる場合がある（二重エディタ） | `[role="dialog"]`を必須にせず、`tweetTextarea_0`を全件列挙して中身で判別 |
| 画像を添付したのに検証で見つからない | 投稿後ページに `tweetPhoto` は無い | `a[href*="/photo/"]` か img src の `/media/` で判定 |
| 入力済みの本文が突然消える | スレッドの `addButton` クリックで `/compose/post` へ遷移が走ることがある | クリックのたびに本文を再照合。消えたら中断して報告 |
| 検証で別のポストを見てしまう | プロフィール最上部は固定ポスト | `socialContext`の有無で固定を除外し2番目以降を見る |
