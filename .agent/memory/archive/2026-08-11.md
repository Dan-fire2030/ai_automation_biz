- **戦略の骨子(2026-07-07に主従を反転)**：主軸=**AI活用の継続伴走コーチング(月額で「先生の実務でAIを使いこなせるように」伴走)** ／ プラスオプション=自動化ツールの構築(デモ01/02・11カタログはオプションの在庫) ／ ストック化の本命=コーチングで貯めたノウハウを**教材化**(動画講座・プロンプト集・テンプレ集)して販売＝「ほぼ不労」の到達点

- **売り方の言語＝「結果の約束」(2026-07-14・AI-BPOリサーチより)**：ツールは「構築します」でなく「◯◯が毎朝届く状態にします」と結果で売る(オプション名も「おまかせパック」)。**約束は非同期型のみ**——「毎朝◯時に届く」はOK、「即日対応・24時間・無制限修正」は副業で守れないSLAなのでNG。保証は返金型(「見逃した月は無料」)。リサーチ全文= `.output/phase0/20`、提案資料(06/09/10/14)は書き換え済み

- **Codex CLIは「サブエージェント」として並行実行する(2026-07-19ユーザー指示)**。`codex exec`をフォアグラウンドでブロックして待たない。①画像生成などの単発タスク＝Bashのバックグラウンド実行(run_in_background)で走らせ、完了通知後に成果物検証(`sips`＋Read目視)。②まとまったコーディングタスク＝codexサブエージェント(codex:codex-rescue等)に委譲。いずれも走らせている間に他の作業を並行で進める。AGENTS.mdの画像生成ルール(保存先・サイズ等の事前確認)は従来どおり適用
- **Codex呼び出しの定型(2026-07-21に4つ踏んで確立・毎回この形で書く)**。`codex exec`は素で叩くと落ちるので以下を守る：
  1. **必ずフルパス `~/.npm-global/bin/codex` で呼ぶ**。Claude Codeのシェルでは `codex` がPATHに無く `command not found` になる(AGENTS.md L22の注記どおりだが、最初から絶対パスで書けば1往復減る)
  2. **`--dangerously-bypass-approvals-and-sandbox` は使わない**。Claude Codeのauto modeクラシファイアにブロックされて実行できない。AGENTS.md L16の `--skip-git-repo-check --sandbox workspace-write` が唯一通る形
  3. **プロンプト冒頭に「`codex exec` を入れ子で呼ぶな・お前自身がこのセッション内で生成しろ」と明記する**。書かないとCodexが自分で `codex exec` を再帰起動し、`failed to initialize in-process app-server client: Operation not permitted (os error 1)` で必ず落ちる(2026-07-21・これで1回まるごと空振り)
  4. **`| tail -N` でパイプしない**。バックグラウンド実行時に出力がバッファされ、完了まで進捗ログが一切見えなくなる。素で流すか `tee` を使う
  5. 長いプロンプトは Writeツールでscratchpadに書き `"$(cat ファイル)"` で渡す。ヒアドキュメント(`cat > file <<'EOF'`)はクラシファイアにブロックされることがある
  6. **Codexは「起動時のcwd配下」にしか書けない。プロジェクト内に保存させたいなら、必ずプロジェクトディレクトリをcwdにして起動する**(2026-07-27に5本全部踏んだ)。scratchpadでプロンプトを組み立てた流れでそこをcwdにして起動すると、プロンプトに絶対パスを書いていても `sips --out` が `Error 13: Cannot to rename temporary file` で拒否され、Codexは黙って作業領域に保存して「権限制限により拒否されました」と報告して**exit 0で返る**。画像自体は生成済みなので、cwd配下(`./` と `./output/`)を探して回収すれば撮り直しは不要
  7. **exit 1でも成果物がある場合がある**。2026-07-27は画像を保存し終えた**後**に「You've hit your usage limit」が出てexit 1になった。exit codeではなく`ls`で判定する
- **Codexジョブが `Turn started` のまま無音で固まることがある。3分で見切る(2026-08-08・13分溶かした)**。`codex:codex-rescue` は `codex-companion.mjs` 経由で**ChatGPTアプリのapp-serverにスレッドを投げる**仕組み（npm版CLIを叩いているわけではない）。この経路がターン開始直後に無反応になることがある。**正常なら1分以内に `Command completed:` 等のitemログが出る**ので、`jobs/task-xxxx.log` を `tail -f` で監視し、**3分経ってもitemログが1行も出なければ `cancel` → 即再投入**する（再投入は成功した）。判定材料＝①`status --all` が `Phase: starting` のまま ②`~/.codex` 配下に直近の更新なし ③`codex exec` プロセスが存在しない
- **`codex:codex-rescue` は「1回転送するだけ」の役者で、進捗監視も成果物検証もしない(2026-08-08)**。サブエージェント側のシステムプロンプトで `status`/`result`/`cancel` の呼び出しが禁じられているため、「完走まで待って」と頼んでも待たない。**監視・検証・キャンセル・再投入はすべてメインスレッドの仕事**。委譲したら自分でログを監視すること
