## 試したこと・結果

### 成功

- **⭐画像挿入の新経路を確立＝OSクリップボード（`osascript`）＋ `cmd+v`**。`file_upload` が死んでいても入る。noteのCDNへ正規にアップロードされ、リロード後も残る（実測済み）
- **⭐アイキャッチも自動化できた（file_upload なしで）**：本文に一時貼り → CDN URLを `fetch` して File 化 → `HTMLInputElement.prototype.click` をフックして捕獲した input へ流し込み → 切り抜き保存 → 一時画像を削除。手順全文は `note-draft-post/SKILL.md`「アイキャッチのルートB」
- **検証方法を改善**：`navigate force:true` が離脱ダイアログを抜けられなかったので、**新しいタブで編集URLを開いて実測**した。これが一番速い（元タブは触らない）
- 冒頭の雑談は**仕事の中身に触れず近況のみ**で構成（ユーザー選択）。**1行目＝顧客の生セリフのルールは維持**し、雑談は2行目以降に置いた

### 失敗・引っかかり（⚠️約40分の損失。全部記録済み）

1. **Codexジョブが `Turn started` のまま13分無音でハング**。`codex:codex-rescue` は npm版CLIではなく**ChatGPTアプリのapp-serverにスレッドを投げる**仕組みで、この経路が固まった。cancel→再投入で復旧（2回目は4分で完走）
   → **3分でitemログが出なければ即cancel→再投入**するルールを MEMORY.md へ
2. **`codex:codex-rescue` は「1回転送するだけ」で待たない**。「完走まで待って」と頼んでも、サブエージェント側の仕様で `status`/`result`/`cancel` が禁止されている
   → **監視・検証・再投入はメインの仕事**と MEMORY.md へ
3. **⚠️`file_upload` がセッション不具合で使えない**。パスの内容と無関係に `expected array, received undefined (path: paths)` が返る。**note-poster が「リポジトリ配下のパスだから」という誤った結論に88ツールコール・約15分を使った**
   → **1回落ちたら切り分け禁止・即ルートB** を SKILL.md と note-poster 定義へ
4. **自分でも空振りした（判断ミス）**：ローカルHTTPサーバー（プライベートネットワーク遮断でリクエストが飛ばない）と `navigator.clipboard.read()`（権限プロンプトが出ない）を先に試した。**どちらも reject せず永久 pending** なので誤診しやすい
   → 「試すな」として SKILL.md に理由つきで記録。**ブラウザに何かを渡す問題は、先にOSクリップボードを疑う**
5. **note-poster が拡張の「未接続」を誤報告**。実際は接続済みで、`tabs_context_mcp` を引数なしで呼んだため「タブグループが無い」で止まっていただけ
   → **`createIfEmpty: true` で呼び直してから報告**を note-poster 定義へ

## 注意点・ブロッカー

### 今回追加された運用ルール（次回これを守れば40分は消える）

- **`file_upload` が `expected array, received undefined (path: paths)` を返したら、パスを変えて試さない。即OSクリップボード経由へ**
- **Codexに投げたら自分でログを監視する。3分無音ならcancel→再投入**
- **ブラウザに画像を渡す問題は、先にOSクリップボードを疑う**（localhost経由・clipboard.read は使えない）
- **サブエージェントにツールの挙動調査をさせない**。代替経路があるなら切り替え、無ければ2回目の失敗で報告させる
- **`scrollIntoView` は `behavior:'instant'` 必須**（省くと直後の座標がスクロール前の値になる）
- **クリック座標のスケールは毎回スクショで確認する**（vol.20では1470×746でCSS座標と1:1。過去記録の0.609倍は環境依存）
